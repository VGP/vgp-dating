# treePL testing ground

This folder is just for running tests using [treePL](https://github.com/blackrim/treePL) to see how the tree responds to different constraints. Here is an example with the current [constraints](/calibrations/calibrations.md):

![treePL constraints test](roadies_v1.1.16b/generated/roadies_v1.1.16b.treePL.png)

Shared input trees and annotations are stored in `../trees/`. Configurations and results for each analysis are kept in its own folder, currently `roadies_v1.1.16b/`. All analysis outputs are kept in `generated/` beneath the configuration directory, including benchmark and replicate results, logs, dated trees, plots, and age reports. Configurations and the launcher stay outside this folder. The launcher recreates `generated/` when needed; it does not delete existing results automatically.

Run the ROADIES launcher with `bash treePL/roadies_v1.1.16b/roadies_v1.1.16b.sh` from the repository root. It benchmarks settings and updates the final configuration with the recommended smooth, opt, optad, optcvad, pliter, and plsimaniter values, plus the moredetail, moredetailad, and moredetailcvad flags. It then runs 200 replicates with random seeds, records the selected seed in the final configuration, and runs that configuration once more to produce the standard result tree and final log. The lowest-objective replicate remains saved separately. Missing or incomplete recommendations stop the launcher. These configuration updates use Python 3; calibration constraints are not changed. Run the plotting script from `treePL/` with `Rscript roadies_v1.1.16b.treePL.R`. Existing results have been moved without rerunning the analysis.

The default fast benchmark uses random CV throughout. It screens a common coarse smoothing grid with three recorded seeds, refines five neighboring half-decade values with those three seeds, and confirms three neighboring values with nine recorded seeds. Confirmation uses the three base seeds plus six distinct, reproducibly derived seeds to increase random holdout sampling. The selected smoothing is the lowest mean score across the shared grid. Final confirmation uses the initial benchmark's recommended PL effort; screening and refinement use the cheaper screening effort. The recommendation explicitly records `cv_method=random` and all confirmation seeds. Thorough mode retains full leave-one-out CV.

The standard treePL implementation fixes random holdout sampling internally rather than reading `randomcviter` or `randomcvsamp` from its config. Extra seeded runs increase sampling effort without relying on those keys. Random and leave-one-out CV are different criteria; the fast-mode result is not described as full-CV validated.
An extension adds a neighboring value and reruns the entire expanded grid for all participating seeds. Scores from different attempts are not pooled. Each stage permits up to six extensions before stopping without a recommendation. Grid positions define the candidate values independently of rounded treePL output. An exact score tie is ordered toward higher smoothing; a boundary winner still requires expansion. Thorough mode retains its existing search. Actual speed savings depend on screening, extensions, and confirmation.

Attempt grids, per-seed scores, configurations, and logs are retained in `generated/treepl_parameter_benchmark/screen_cv_attempts_*`, `refine_cv_attempts_*`, and `confirm_cv_attempts_*` for fast mode. Each attempt records its winning grid index, percentage gap to the runner-up, and whether individual seed winners disagree in `decision.tsv`. Invalid, nonfinite, duplicate, or missing candidate scores stop the fast search. Stopping boundaries include a small numerical margin so rounding does not omit the intended last grid value. Failed CV processes also retain score counts and exit status in `failed_cv_*` directories. Prime trial seeds are explicit and recorded in `prime_seeds.tsv`.

Prime selection parses the three optimizer numbers and three optional flags by name and selects their complete combination together. Omitted flags are recorded explicitly as 0; recommended flags are recorded as 1. The selected flags apply throughout PL and CV benchmarking and are enabled or commented out in the final configuration before replicates run. Old active flags are removed when no longer recommended. Invalid prime recommendation blocks are excluded, with their logs retained in `failed_prime_*`.

Replicate selection requires a finite numeric objective and reports attempted, successful, and failed counts in `replicate_counts.txt` and the selection record. Failed attempts are excluded; the best successful replicate is retained even if some attempts fail. Previous selection artifacts are cleared at the start of a rerun.

After updating the selected seed, the launcher saves `generated/roadies_v1.1.16b.final.config` and runs that snapshot from the analysis directory, so its relative paths retain their meaning. Final validation requires R with the ape package: the output must parse as a tree with finite, nonnegative branch lengths and the same taxa as the input. A finite final objective is also required. `generated/final_run_status.txt` distinguishes a running or failed workflow from a validated completed analysis and records both final and selected-replicate objectives plus replicate counts. The previous final tree is removed just before the final run to prevent stale output from passing validation.

Fast CV prints the stage, grid range, seed position, every completed smoothing value and score, and elapsed time. While a value is running, it prints a heartbeat every 30 seconds with the completed-value count and the latest available optimization/CV activity. Full process logs remain saved with each attempt. These progress messages are activity reports, not runtime estimates.
