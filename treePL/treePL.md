# treePL testing ground

This folder is just for running tests using [treePL](https://github.com/blackrim/treePL) to see how the tree responds to different constraints. Here is an example with the current [constraints](/calibrations/calibrations.md):

![treePL constraints test](roadies_v1.1.16b/generated/roadies_v1.1.16b.treePL.png)

Shared input trees and annotations are stored in `../trees/`. Configurations and results for each analysis are kept in its own folder, currently `roadies_v1.1.16b/`. All analysis outputs are kept in `generated/` beneath the configuration directory, including benchmark and replicate results, logs, dated trees, plots, and age reports. Configurations, the launcher, and the topology-specific plotting script stay outside `generated/`. The launcher recreates `generated/` when needed; it does not delete existing results automatically.

Run the ROADIES launcher with `bash treePL/roadies_v1.1.16b/roadies_v1.1.16b.sh` from the repository root. It benchmarks settings and updates the final configuration with the recommended smooth, opt, optad, optcvad, pliter, and plsimaniter values, plus the moredetail, moredetailad, and moredetailcvad flags. It then runs up to 200 replicates with random seeds, records the selected seed in the final configuration, and runs that configuration once more to produce the standard result tree and final log. The lowest-objective replicate remains saved separately. Missing or incomplete recommendations stop the launcher. These configuration updates use Python 3; calibration constraints are not changed. The launcher finishes by running `roadies_v1.1.16b.treePL.R` from `treePL/roadies_v1.1.16b/`, generating the plot, scientific-name tree, and calibrated-node age table. Plotting output is saved in `generated/plotting.log`; a plotting failure stops the launcher with `stage=plotting`, and the workflow is marked complete only after plotting succeeds. Plotting requires the rphylopic, phytools, plotrix, and png R packages and internet access for silhouettes. To rerun plotting alone, use `Rscript roadies_v1.1.16b.treePL.R` from `treePL/roadies_v1.1.16b/`. Existing results have been moved without rerunning the analysis.

The default fast benchmark starts with adaptive prime searching, then uses one recorded seed for initial PL convergence with a buffer and full leave-one-out CV. Screening uses eight decade-spaced values from 100 through 0.00001. All CV rounds use the initial benchmark's recommended pliter and plsimaniter, with cviter=3 and cvsimaniter=5000, and omit `thorough`. PL convergence checks and production runs retain `thorough`. The default seed is 1729; random seed mode generates and records one seed. The separate thorough profile retains its existing multiple-seed random-CV tuning and full-CV validation.

After the eight-value broad sweep, fast mode runs up to four five-point refinements (five rounds total). Each refinement spans the preceding winner’s immediate neighbors and halves the log10 spacing: 0.5, 0.25, 0.125, then 0.0625 decades. It stops early after two consecutive rounds with an interior winner and a nonnegative improvement below 0.5% in the best CV score relative to the preceding round. A worsening score resets the streak; zero-to-zero counts as no improvement. Boundary winners must be resolved by expansion before a round can qualify. Extensions are additional attempts within a round, not additional refinement rounds.

Each round selects using only its own scores. Overlapping scores remain diagnostic checks of restart sensitivity. `full_cv_rounds.tsv` records winners, scores, signed percentage improvements, and the stopping streak. The final recommendation records the number of rounds and whether it stopped for `small_improvement` or `max_rounds`; reaching the cap does not imply convergence. Final PL convergence is checked at the last round’s selected smoothing before the configuration is updated.

Fast mode does not perform an independent seed check; its final recommendation records `cv_method=full` and `cv_seed_check=not_performed`. The later production replicates explore optimization at the chosen settings; they do not re-evaluate smoothing.

A boundary winner extends the grid by two values in that direction and reruns the entire continuous descending grid. Earlier points are retained. Scores from different attempts are not pooled. Each stage permits up to six extensions before stopping without a recommendation. Grid positions define candidates independently of rounded treePL output. An exact score tie is ordered toward higher smoothing; a boundary winner still requires expansion. There is no wall-time cutoff, and duration depends on optimization and extensions.

Fast-mode score tables use stage names `screen`, `refine`, `fine`, `round4`, and `round5`, for example `full_cv_round4_scores.tsv`. Refinement stages have matching `_summary.tsv`, `_overlap.tsv`, and `_recommendation.txt` files. Overlap tables report signed percentage score changes; a zero previous score with a nonzero current score is marked `NA`. Attempt grids, scores, configurations, and logs are retained in stage-specific directories such as `screen_cv_attempts_*` and `round4_cv_attempts_*` under `generated/treepl_parameter_benchmark/`. Grid indices use sixteenth-decade units (`smoothing = 10^(index/16)`). Each attempt records its winning grid index and percentage gap to the runner-up in `decision.tsv`. Invalid, nonfinite, duplicate, or missing candidate scores stop the fast search. Stopping boundaries include a small numerical margin so rounding does not omit the intended last grid value. Failed CV processes also retain score counts and exit status in `failed_cv_*` directories. Prime trial seeds are explicit and recorded in `prime_seeds.tsv`.

Prime selection parses the three optimizer numbers and three optional flags by name and keeps their complete combination together. Both profiles use adaptive prime searching: at least 40 successful trials, up to 200 launched trials, and two concurrent processes by default. Trial seeds are distinct and recorded. Every ten successful trials, early stopping checks whether the leading combination has at least 25% support, a 10-percentage-point lead, and the same leading combination across three consecutive checkpoints; otherwise the search continues to its maximum. The most frequent complete combination is selected. Omitted flags are recorded explicitly as 0; recommended flags are recorded as 1. The selected flags apply throughout PL and CV benchmarking and are enabled or commented out in the final configuration before replicates run. Old active flags are removed when no longer recommended. Invalid prime recommendation blocks are excluded, with their logs retained in `failed_prime_*`.

Replicates stop once at least 20 runs have succeeded and at least 10 successful runs match the current lowest objective at printed precision, regardless of order. A newly lower objective starts a new match count; worse or failed runs do not erase existing matches. The requested run count (200 in the launcher) remains the maximum, and smaller explicit counts are honored. This criterion measures objective agreement, not identical node ages or proof of a global optimum. Counts and the selection record include actual attempts, the requested maximum, matches to the best objective, and the stopping reason. The final workflow status also records these details.

Replicate selection requires a finite numeric objective and reports attempted, successful, and failed counts in `replicate_counts.txt` and the selection record. Failed attempts are excluded; the best successful replicate is retained even if some attempts fail. Previous selection artifacts are cleared at the start of a rerun.

After updating the selected seed, the launcher saves `generated/roadies_v1.1.16b.final.config` and runs that snapshot from the analysis directory, so its relative paths retain their meaning. Final validation requires R with the ape package: the output must parse as a tree with finite, nonnegative branch lengths and the same taxa as the input. A finite final objective is also required. `generated/final_run_status.txt` distinguishes a running or failed workflow from a validated completed analysis and records both final and selected-replicate objectives plus replicate counts. The previous final tree is removed just before the final run to prevent stale output from passing validation.

Fast CV prints the stage, grid range, seed position, every completed smoothing value and score, and elapsed time. While a value is running, it prints a heartbeat every two minutes with the completed-value count and the latest available optimization/CV activity. Full-CV heartbeats also report approximate completed leave-outs and a percentage for the current smoothing value, using the input tree’s tip count. Counts reset for each value and may lag or undercount because parallel log output can be buffered or interleaved; the saved CV score remains the completion check. If R/ape cannot supply the tip count, the heartbeat reports a count without a percentage. Full process logs remain saved with each attempt. These progress messages are activity reports, not runtime estimates.
